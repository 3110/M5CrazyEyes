# M5CrazyEyes

M5Stack Stopwatch の画面に目の画像を表示し，ESP-NOW で受信した `eye_id` に応じて開閉状態を切り替えるファームウェアです。同じファームウェアを左右のデバイスへ書き込み，それぞれの `eye_id` を本体のボタンで設定できます。M5Stack Chain DualKey を使った専用コントローラーのファームウェアも含みます。

| 開いた状態 | 閉じた状態 |
| --- | --- |
| ![開いた目](data/crazy_eyes_open.jpg) | ![閉じた目](data/crazy_eyes_close.jpg) |

## 動作仕様

- `eye_id` はデバイスごとに NVS へ保存します。左目は `L`，右目は `R` です。
- `eye_id` は本体のボタンで設定します。起動時にAボタンを1秒間長押しすると左目に，Bボタンを1秒間長押しすると右目になります。
- `eye_id` がない初回起動では，画面に `A = LEFT` / `B = RIGHT` を表示して，どちらかのボタンが押されるまで待ちます。
- 起動するたびに，設定されている側を `LEFT` または `RIGHT` として1秒間表示してから目を表示します。画面の下側にはファームウェアの名前とバージョンも表示します。
- 起動時に本体のステータスLEDを消灯します。目の表示以外が光らないようにするためです。
- Aボタンを押すたびに，電池残量のアークゲージを表示／非表示できます。起動直後は非表示です。
- ESP-NOW のペイロードは，`eye_id` と操作コマンドからなる2バイトです。
- Chain DualKeyのキーを押している間は目を閉じ，離すと目を開きます。押し続ける時間に制限はありません。
- 短くタップしてから素早くもう一度押し続けると，押している間だけ高速まばたきします。
- 閉じる，または高速まばたきのコマンドが600ms間届かなければ，通信切断と判断して自動的に目を開きます。
- 表示デバイスの画面をタッチしている間は目を閉じ，指を離すと3回パチパチとまばたきします。片方を触ると，反対の目も一緒に反応します。
- 本体を左右に傾けると，重力の向きへ瞳が寄ります。傾けるのをやめると，わずかに揺り戻してから止まります。
- 動きも操作も受信もない状態が続くと，30秒ごとに段階的に目が落ちていき，2分後に閉じます。何か起きると即座に見開きます。
- 開くコマンドは，キーを離してから50ms間隔で3回送信します。1つでも届けば目が開きます。
- キー操作が10秒間なければ，コントローラーが両目を数秒おきにランダムにまばたきさせます。キーに触れると即座に止まり，手動操作が優先されます。
- ランダムまばたきは，片方のキーを押したままもう片方を短くタップするとオン／オフできます。
- 開閉2枚の画像は起動時に一度だけデコードして PSRAM 上のキャンバスへ保持し，表示はキャンバスの転送だけで行います。1フレームあたり約30msで描画できるため，高速まばたきは設定どおり100ms間隔で切り替わります。
- `ESP_NOW_CHANNEL` は `0` です。この値は無線チャンネル0を表すのではなく，ライブラリ側で Wi-Fi チャンネルを固定しない設定です。
- `crazy-eyes-controller` は Chain DualKey のキー1へ左目を表す `L`，キー2へ右目を表す `R` を割り当て，開く，閉じる，高速まばたきのコマンドをブロードキャストします。

- M5Stack Stopwatch
  - 左右を同時に使う場合は2台必要です。

## ビルド

表示側の `crazy-eyes` はデフォルト環境です。

```sh
pio run
```

コントローラー側は環境名を指定してビルドします。

```sh
pio run -e crazy-eyes-controller
```

両方をまとめてビルドすることもできます。

```sh
pio run -e crazy-eyes -e crazy-eyes-controller
```

ビルド済みのファームウェアは，それぞれ次のディレクトリに生成されます。

```text
.pio/build/crazy-eyes/
.pio/build/crazy-eyes-controller/
```

表示側には，診断ログを有効にした `crazy-eyes-debug` 環境もあります。`crazy-eyes` を継承しているので，設定はそちらを変更すれば両方に反映されます。

```sh
pio run -e crazy-eyes-debug
```

## コントローラー

`crazy-eyes-controller` は M5Stack Chain DualKey の2つのキーを監視し，`eye_id` と操作コマンドを ESP-NOW でブロードキャストします。

| Chain DualKey | `eye_id` |
| --- | --- |
| キー1 | `0x4C`（ASCII の `L`，左目） |
| キー2 | `0x52`（ASCII の `R`，右目） |

操作方法は次のとおりです。

| 操作 | 目の動作 |
| --- | --- |
| キーを押す | 閉じる |
| キーを押し続ける | 閉じた状態を維持する |
| キーを離す | 開く |
| 250ms以内の短いタップ後，300ms以内にもう一度押し続ける | 高速まばたきする |
| 高速まばたき中にキーを離す | 開く |
| 片方のキーを押したまま，もう片方を短くタップする | ランダムまばたきをオン／オフする |
| 10秒間どのキーも操作しない | ランダムまばたきを始める（オンのとき） |

送信データは長さが2バイトで，1バイト目が `eye_id`，2バイト目が操作コマンドです。

| コマンド | 値 |
| --- | --- |
| 開く | `0x00` |
| 閉じる | `0x01` |
| 高速まばたき | `0x02` |
| 短くまばたき | `0x03` |
| 起きている | `0x04` |
| 触られている | `0x05` |

コマンドの最上位ビット（`0x80`）は**自動送信の印**です。ランダムまばたきで送るコマンドにだけ立てます。オン／オフの応答パターンはキー操作への返事なので，印は立てません。表示側はこの印を2つの用途に使います。

- **活動として数えない** … これで起きてしまうと，コントローラーが動いている限り眠らなくなります
- **手動操作を優先する** … 印の付いたコマンドは，手動操作のコマンドを受けてから600ms以内なら無視します。これがないと，反対の目がタッチされて閉じている最中に，ランダムまばたきが割り込んで目を開けてしまいます

「短くまばたき」「起きている」「触られている」はコントローラーではなく，**表示デバイス同士**で使います。タッチされた表示デバイスが反対の目へ送り，両目を揃えるためのものです。「起きている」は目の状態を変えず，活動があったことだけを伝えます。「触られている」を受け取った側は，自分が触られたときと同じ扱いになり，コントローラーからの指示より優先します。

「起きている」は次の場面で送ります。

- **本体の動きを検知したとき**（5秒に1回まで）
- **Aボタンを押したとき**
- **起動したとき**

目の状態を変えないコマンドを別に用意しているのは，「開く」で代用すると，コントローラーがキーで目を閉じている最中に一瞬開いてしまうからです。

閉じるコマンドと高速まばたきコマンドは，キーを押している間，200ms間隔で再送します。開くコマンドは，取りこぼしても確実に目が開くように，キーを離してから50ms間隔で3回送信します。キーを離した直後にもう一度押した場合は，未送信の開くコマンドを取り消します。高速まばたきの画像は表示側で100msごとに切り替えます。実装は [m5stack-esp-now のサンプル](https://github.com/3110/m5stack-esp-now/blob/main/examples/chain-dualkey-broadcast/main.cpp)をもとに，このプロジェクトに必要なキー入力とブロードキャスト処理を拡張しています。

### ランダムまばたき

キー操作が10秒間なければ，コントローラーが両目へ乱数の間隔でまばたきのコマンドを送ります。何もしていないときに目が生きているように見せるための動作です。

- 間隔は2〜6秒のランダムで，1回のまばたきは90〜150msです。15%の確率で2回続けてまばたきします。
- キーに触れた瞬間に止まり，手動操作が優先されます。手を止めれば10秒後に再開します。
- まばたきの指示はコントローラーが両目へ同時にブロードキャストするため，左右が必ず揃います。

表示側のファームウェアとプロトコルは変更していません。ランダムまばたきは，コントローラーが既存の閉じる／開くコマンドを乱数のタイミングで送っているだけです。そのため，この機能を使うのに表示デバイスを書き込み直す必要はありません。

#### オン／オフ

片方のキーを押したまま，もう片方を短くタップするとオン／オフが切り替わります。切り替わったことは目の動きで分かります。

| 応答 | 意味 |
| --- | --- |
| 両目が3回，素早くまばたきする | オンになった |
| 両目が0.6秒ほど閉じてから開く | オフになった |

どちらもキー操作では作れないパターンなので，通常のまばたきと区別できます。

両キーを同時に押す操作は，従来どおり両目を閉じるだけです。タップしたキーが押したままのキーより200ms以上あとに押されていることを条件にしているため，両キーを同時に押して離す順序がずれても誤ってトグルしません。

オン／オフの状態はコントローラーが保持し，保存はしません。電源を入れ直すとオンに戻ります。自動開始そのものを止めたい場合は，`src/crazy-eyes-controller/main.cpp` の `IDLE_BLINK_DELAY_MS` を `0` にします。

## `eye_id` の設定

設定は本体の2つのボタンだけで行います。シリアルコンソールは不要です。

| 操作 | 結果 |
| --- | --- |
| Aボタンを押しながら起動し，1秒間押し続ける | 左目（`L`）として設定 |
| Bボタンを押しながら起動し，1秒間押し続ける | 右目（`R`）として設定 |
| どちらも押さずに起動 | 保存済みの設定で起動 |

長押しを要求しているのは，電源投入時にうっかり触れただけで設定が変わらないようにするためです。ボタンを離すのは，画面に `LEFT` または `RIGHT` が表示されてからにしてください。

### 初回設定

NVS に `eye_id` がない場合は，画面に次の表示が出て，どちらかのボタンが押されるまで待機します。この状態では長押しは不要で，短く押すだけで確定します。

```text
A = LEFT
B = RIGHT
```

### 設定の確認

起動するたびに，設定されている側を1秒間表示してから目の画像へ切り替わります。押すボタンを間違えた場合は，もう一度反対のボタンを押しながら起動し直してください。

画面の下側には，ファームウェアの名前とバージョンを合わせて表示します。書き込んだファームウェアの世代を確認するのに使えます。

```text
      LEFT

M5CrazyEyes v0.0.2
```

同じ内容は起動直後にシリアルへも出力します。

115200 bpsのシリアルコンソールを開いていれば，同じ内容をログでも確認できます。

```text
Saved eye ID: R (right)
Using eye ID: R (right)
```

- 設定値は NVS に保存されるため，通常のファームウェア更新後も維持されます。
- 保存は値が変わるときだけ行います。同じ側を選び直しても NVS へは書き込みません。
- どちらの物理ボタンがAでBかは，`src/crazy-eyes/main.cpp` の `BTN_A_EYE_ID` と `BTN_B_EYE_ID` で入れ替えられます。

`crazy-eyes-controller` と組み合わせる場合は，左目の表示デバイスを `LEFT`，右目の表示デバイスを `RIGHT` に設定します。

## 使い方

1. `crazy-eyes` を書き込んだ表示デバイスを，Aボタンを押しながら起動して左目に，Bボタンを押しながら起動して右目に設定します。
2. `crazy-eyes-controller` を Chain DualKey へ書き込みます。
3. コントローラーと表示デバイスを起動します。
4. キー1を押している間は左目が，キー2を押している間は右目が閉じます。
5. キーを離すと，対応する目が開きます。
6. 高速まばたきさせる場合は，対象のキーを短くタップし，300ms以内にもう一度押し続けます。

コントローラーと表示デバイスは，同じ実際の Wi-Fi チャンネルを使用する必要があります。`ESP_NOW_CHANNEL=0` の場合，どちらもチャンネルを明示的に変更しません。

## タッチ操作

表示デバイスの画面をタッチしている間は目を閉じ，指を離すと3回パチパチとまばたきしてから元の状態へ戻ります。コントローラーがなくても動きます。

**片方を触ると，反対の目も一緒に反応します。** タッチした表示デバイスが，反対の目へ「触られている」コマンドを200ms間隔で送り，離すときに「短くまばたき」を送ります。

受け取った側は，自分が触られたときと**同じ扱い**になります。これにより，コントローラーからの指示より優先されます。たとえば高速まばたき中にタッチすると，両目とも止まって閉じ，離すと両目でまばたきしてから高速まばたきへ戻ります。片方だけが止まる，といった非対称は起きません。

触っている側の電源が落ちたり通信が切れたりした場合は，600ms届かなければこの状態を抜けて通常の表示へ戻ります。

タッチはコントローラーからの指示とは別のレイヤーとして扱います。タッチしている間は遠隔側の描画を止めますが，受信したコマンドの反映と通信切断の判定は続けているため，指を離した時点の正しい状態へ戻ります。高速まばたき中にタッチした場合は，パチパチのあとに高速まばたきが再開します。

まばたきの回数と速さは `src/crazy-eyes/main.cpp` の次の定数で調整できます。

| 定数 | 内容 |
| --- | --- |
| `TOUCH_BLINK_COUNT` | 指を離したあとにまばたきする回数 |
| `TOUCH_BLINK_CLOSE_MS` / `TOUCH_BLINK_OPEN_MS` | 閉じている時間と開いている時間 |

起動時に，タッチパネルが使える状態かをシリアルへ出力します。被り物やレンズ越しに取り付けると反応しないことがあるため，装着した状態で動作を確認してください。

```text
Touch panel: enabled
```

## 視線の動き

本体を左右に傾けると，重力の向きへ瞳が寄ります。人形の目が重みで転がるような動きで，コントローラーもタッチも要りません。傾けるのをやめると，バネの効いた動きでわずかに揺り戻してから止まります。

傾きは内蔵の6軸IMU（BMI270）から求めます。重力の向きを見ているので，加速度の積分による誤差の蓄積はありません。左右方向のみで，上下には動きません。

虹彩と瞳は画像に含めず，**実行時に円で描いています**。`data/crazy_eyes_open.jpg` は虹彩と瞳を除いた背景で，まぶたは含まれます。元のSVGの寸法から，虹彩が白目の外へはみ出さない範囲を確認してあります。

| 項目 | 値 |
| --- | --- |
| 白目の見えている範囲 | 縦 y=102〜369，中央行の横 x=64〜405 |
| 虹彩 | 中心 (234, 234)，半径 122，`#29C7FF` |
| 瞳 | 同じ中心，半径 79，`#0D0D0D` |
| 左右に動かせる限界 | ±48px（実装では余裕をみて ±40px） |

`src/crazy-eyes/main.cpp` の定数で調整できます。

| 定数 | 内容 |
| --- | --- |
| `GAZE_MAX_OFFSET` | 瞳を寄せる最大量 |
| `GAZE_TILT_LIMIT` | ここまで傾けると振り切れます。既定は30度相当 |
| `GAZE_DIRECTION` | 傾ける向きと視線の向きが逆なら `-1.0F` にします |
| `GAZE_SPRING` / `GAZE_DAMPING` | 追従の速さと揺り戻しの量 |

取り付けの向きによっては，参照する加速度の軸が変わります。この機体ではX軸が画面の縦方向で，横方向はY軸でした。軸そのものを変える場合は `gazeTiltSource()` を書き換えてください。

確認用の `crazy-eyes-debug` 環境を用意しています。加速度と視線量，眠りの進行をシリアルへ出力します。

```sh
pio run -e crazy-eyes-debug -t upload
```

```text
accel x=+0.02 y=+0.45 z=-0.89 -> gaze=-36
sleep: idle=42s step=1 motion=0.008 peak=0.031
```

## 眠りの動作

動きもタッチも受信もない状態が続くと，だんだん目が落ちていきます。机に置いて放置すると，そのうち寝てしまいます。

| 無操作の時間 | 状態 |
| --- | --- |
| 30秒 | 少し眠そう |
| 60秒 | はっきり半目 |
| 90秒 | とろん |
| 2分 | 目を閉じる |

何か起きると，一段ずつ戻すのではなく**即座に見開きます**。

「何か起きた」と判断するのは次の3つです。

- **本体が動いた** … IMUの加速度の変化を見ます。装着していれば完全に静止することはないので，身につけている間は眠りません
- **画面をタッチした**
- **ESP-NOW で手動操作のコマンドを受信した**

**ランダムまばたきのコマンドは活動として数えません。** これは「誰も操作していない」という意味の通信なので，これで起きてしまうとコントローラーの電源が入っている限り永久に眠らなくなります。手動操作と区別するため，コントローラーは自動で送るコマンドに印を付けています（[コントローラー](#コントローラー)を参照）。眠ったあとも自動まばたきのコマンドは届きますが，無視されて目は閉じたままです。手動でキーを押せば即座に見開きます。

眠さは左右で揃っている必要があります。受信するコマンドは両目に共通ですが，**タッチと本体の動きは片方にしか届きません**。タッチした表示デバイスは反対の目へも同じ反応を伝え、動きを検知した表示デバイスは「起きている」ことを5秒に1回まで反対の目へ知らせます。

動きについては，起きた瞬間に伝えるだけでは足りません。片方だけが振動を拾い続けている場合，**その側には起床という遷移が一度も起きない**ため，伝えるきっかけが無いまま反対側だけが眠ってしまいます。活動している間は定期的に知らせ続ける必要があります。

左右を別々に起動した場合も，**後から起動した側が先に動いていた側を起こします**。起動直後は必ず起きた状態なので，そちらへ揃えるほうが自然です。

`src/crazy-eyes/main.cpp` の定数で調整できます。

| 定数 | 内容 |
| --- | --- |
| `SLEEP_STEP_MS` | 一段進むまでの無操作時間 |
| `MOTION_THRESHOLD` | 動いたと判断する加速度の変化量 |

## 電池残量の表示

表示デバイスのAボタンを押すと，画面の外周に沿ったアークで電池残量を表示します。もう一度押すと消えます。起動直後は非表示で，この状態は保存しないため，電源を入れ直すと非表示に戻ります。

- ゲージは12時の位置から時計回りに伸び，一周で100%です。
- 残量に応じて色が変わります。50%超は緑，20〜50%は黄，20%以下は赤です。
- 充電中は水色になり，0.6秒ごとに明るさが切り替わって点滅します。残量は充電中もそのまま読めます。
- 残量の読み取りに失敗した場合は，目盛りだけを表示します。

残量は電池電圧から求めているため，画面の明るさや ESP-NOW の送信で数%揺れます。5%刻みに丸めて表示のちらつきを抑えています。読み取りは10秒ごとで，表示が変わるときだけ描き直すため，高速まばたきの100ms間隔には影響しません。

## カスタマイズ

### ESP-NOW のチャンネル

`platformio.ini` の次の定義でチャンネルを変更できます。

```ini
-DESP_NOW_CHANNEL=0
```

`ESP_NOW_CHANNEL=0` では Wi-Fi チャンネルを固定しません。チャンネルを明示する場合は1から13の範囲に変更し，送信側にも同じ実際の Wi-Fi チャンネルを設定してください。

### コントローラーの `eye_id`

コントローラーが送信する値は，`src/crazy-eyes-controller/main.cpp` の `KEY1_EYE_ID` と `KEY2_EYE_ID` で変更できます。表示側の NVS に設定した `eye_id` と一致させてください。

| 定数 | 内容 |

### 表示画像

次の JPEG ファイルを差し替えて再ビルドすると，表示する目を変更できます。

```text
data/crazy_eyes_open.jpg    # 完全に開いた状態
data/crazy_eyes_open1.jpg   # 少し眠そう
data/crazy_eyes_open2.jpg   # はっきり半目
data/crazy_eyes_open3.jpg   # とろん
data/crazy_eyes_close.jpg   # 閉じた状態
```

開いた状態の4枚には，次の2つの制約があります。

- **虹彩と瞳を含めません。** 実行時に円で描くため，白目を塗った状態にしてください。まぶたは画像に含めます
- **白目は純白（`#FFFFFF`），肌色は青成分の低い色にしてください。** 起動時に画像を走査して，行ごとに白目が見えている範囲を求め，虹彩をそこへ収めて描いています。判定には**青成分だけ**を使います。白目(255)と肌色(138)は青が大きく離れており，輪郭線はどちらも青が小さいため確実に分けられます。**画像の角は黒で塗ります**。白いままだと白目と誤判定されます（円形ディスプレイなので角は表示されません）

元となる SVG は `design/` にあります。ImageMagick で書き出せます。

```sh
magick -background black design/crazy-eyes-open1.svg -resize 468x468 -alpha remove -alpha off \
  -sampling-factor 4:4:4 -interlace none -quality 95 -strip data/crazy_eyes_open1.jpg
```

**開いた状態の4枚は 4:4:4・品質95で書き出します。** この絵柄は黒い輪郭線と白い白目が隣り合う高コントラストな画像で，JPEGのデコード時にリンギングが出ます。4:2:0 は色成分を2×2画素で平均するため，白目の判定に使う青成分が境界でにじみます。閉じた目の画像は走査しないので，この制約はありません。

`design/crazy-eyes-open.svg` には虹彩と瞳のレイヤーが含まれているため，そのまま書き出す場合はそれらのパスを取り除いてください。`crazy-eyes-open1.svg` 〜 `open3.svg` は，上まぶたを平行移動して，露出する白目の上部を肌色で埋めたものです。

画像はファームウェアへ埋め込まれ，起動時に一度だけデコードして PSRAM 上のキャンバスへ保持します。キャンバスは5枚で PSRAM を約2.1MB使用します。確保に失敗した場合は，表示のたびに JPEG をデコードする動作へ自動的に切り替わります。

デコードは起動時の一度だけなので，画像の形式は表示の速さには影響しませんが，起動時間を短くするには次の条件を満たす画像が有利です。

- 画面と同じ 468×468 ピクセル
  - 画面サイズと異なる場合は拡大縮小の処理が入り，デコードに数倍の時間がかかります。
- ベースライン JPEG であること
  - 開いた状態の4枚は，白目の判定精度を優先して 4:4:4 にしています。4:2:0 より MCU が小さくデコードは遅くなりますが，起動時の一度だけなので表示の速さには影響しません。

ImageMagick で変換する場合の例です。

```sh
magick input.png -resize 468x468! -sampling-factor 4:2:0 -interlace none -quality 88 -strip data/crazy_eyes_open.jpg
```

## トラブルシューティング

### `config/platformio-m5stack.ini` が見つからない

サブモジュールが取得されていません。プロジェクトのルートで次を実行してください。

```sh
git submodule update --init --recursive
```

### 書き込み先ポートが見つからない

USB ケーブルがデータ通信に対応していることを確認し，`pio device list` で認識されているポートを確認してください。複数のポートがある場合は，`--upload-port` で対象を指定します。

### ボタンを押しても `eye_id` が変わらない

ボタンは，リセットまたは電源投入の瞬間から押し続けてください。1秒間の長押しが必要です。画面に `LEFT` または `RIGHT` が表示されたら離して構いません。表示された側が期待と逆であれば，反対のボタンを押しながら起動し直してください。

### ESP-NOW を受信しても表示が変わらない

次の項目を確認してください。

- 送信側と受信側が同じ実際の Wi-Fi チャンネルを使用しているか
- ペイロードが `[eye_id, 操作コマンド]` の2バイトか
- 起動時に表示される `LEFT` / `RIGHT` と送信値が一致しているか
- 送信側と受信側が ESP-NOW で通信できる距離にあるか

### Chain DualKeyを押しても送信されない

`crazy-eyes-controller` 環境を書き込んでいることを確認してください。115200 bpsのシリアルコンソールを開くと，ESP-NOW の初期化失敗や送信失敗を確認できます。
